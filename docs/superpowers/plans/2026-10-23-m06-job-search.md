# M06 Job Search Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver honest provider-attributed job search, freshness reporting, and locally saved jobs/searches through MCP.

**Architecture:** Reuse M05's trusted adapter/router and shared MCP transport patterns while isolating the job domain in its own core contracts. Provider authentication and provider selection are host-owned, with default zero providers. Persist saved entries only in explicit local storage.

**Tech Stack:** Node.js 24, TypeScript 5, Vitest, Zod 4, existing MCP SDK, pnpm monorepo.

**Spec:** `docs/superpowers/specs/2026-10-23-m06-job-search-design.md`.

## Global constraints

- LinkedIn Talent API access is partner-gated and must never be claimed from standard OAuth scopes.
- No bundled external source, browser scraping, arbitrary endpoint, authentication bypass or automated job applications.
- No fabricated posting dates, remote eligibility, sponsorship, salary, canonical URLs, confidence or source identity.
- Canonical query limit 1–50, default 10; strict UTC instants and local validation before provider effects.
- No provider => unavailable with no posts field; mixed success/failure => partial and per-provider audit outcomes.
- Read-only discovery is separate from explicit local save mutations; no linked account writes.
- Each behavioral task gets genuine focused RED, GREEN, relevant full suite/quality checks, and remote checkpoint CI.

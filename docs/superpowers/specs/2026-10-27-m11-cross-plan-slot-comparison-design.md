## Contract

- New typed MCP tool `linkedin.calendar.plans.compare_slots`, with input exactly `{ plans:[{id:UUID, expectedRevision:positiveSafeInteger},{id:UUID,expectedRevision:positiveSafeInteger}] }`. Exactly two entries, distinct IDs, original caller plan order meaningful. Host opts in to `LINKEDIN_MCP_CALENDAR_STORE_PATH` and uses STDIO. No caller-supplied filesystem path, URL, provider or credentials. All HTTP calls return `unsupported/local_store_not_available` before inspecting injected private-store getters.
- Call `store.get({id})` once for **each** ID and never call create/update/list/remove. If missing, return fixed sanitized `not_found`; if either snapshot revision differs, return fixed `revision_conflict`; malformed store output returns sanitized `invalid_output`. No stale approval, actual queue, provider call, reservation or publication.
- Pure `compareLocalCalendarPlanSlots(input:{plans:unknown;expectedRevisions:unknown}): Readonly<LocalCalendarPlanSlotComparison>` validates strict own-data, arrays with exact positions, no proxies/getters/accessors/hostile inherited descriptors/secret extra fields, proper plan UUID and positive safe revisions, canonical UTC timestamps (createdAt <= updatedAt), full M11.0 preview semantics, distinct plan IDs and bounded content. `plans` contains exactly two full stored records; `expectedRevisions` contains exactly two positive safe integers.
- Output has exact root fields `kind:'local_cross_plan_utc_slot_comparison'`, `status:'planning_only'`, `origin:'caller_defined'`, `persistence:'private_local'`, `execution:'not_queued'`, `approval:'not_evaluated'`, `publication:'not_attempted'`, `snapshotConsistency:'independent_revisions_not_atomic'`, `plans:[{id,revision,referenceUtc,itemCount}]`, `collisions:[{plannedAtUtc,items:[{planId,itemId,kind,manualOnly}]}]`, `counts:{comparedPlans:2,collisionMinutes:number,collisionItems:number}`, `warnings`. All items are **metadata-only**; no labels, bodies, paths, credentials, approvals or media references. Compare exact UTC minutes occurring in **both** plans (same-plan-only duplicates do not count); sort collision minutes ascending and place item metadata in caller plan order, preserving original item position for same-minute ties.
- Fixed warnings: `caller_planned_only`, `independent_revisions_not_atomic`, `no_scheduling_or_publishing`, `approval_not_evaluated`, and conditional `cross_plan_same_minute_collision`. Do not call planning conflicts actual scheduled conflicts, execution readiness, overdue, queued, approved or published.
- Two store reads are separate; the result is the observed pair of revisions, **not an atomic multi-plan transaction** or locked future slot. A later concurrent update might invalidate either plan; no coherence, reservation, delivery or provider claim.
- Enforce existing dual structured/text MCP response and complete raw HTTP/SSE <=256KiB, pure JSON <=32KiB. Read result cannot be confused with execution receipts. Preserve existing M11.0–M11.2 behavior and all security path hardening. Count expected in-memory MCP tools 58→59, real compiled tools 62→63. `calendar.plans` remains LOCAL_ONLY, unavailable by default; `schedule.create` remains unavailable.

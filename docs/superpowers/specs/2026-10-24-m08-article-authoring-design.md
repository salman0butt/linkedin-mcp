# M08 Article Authoring Engine — Design

Date: 2026-10-24. Requirement: `R-M08-ARTICLE`. Milestone: `docs/milestones/M08-article-engine.md`.

## Intent, approach and scope

An MCP client should help a user progressively prepare a **local, reviewable, long-form article package**: research brief, attributed source notes, outline, structured draft blocks, editorial review checklist, media/SEO metadata, deterministic preview and a companion short post. The user retains ownership of editing and review. The engine must not pretend to have researched, fact-checked, generated images, obtained a native LinkedIn publishing entitlement or published anything.

Three approaches were considered: (1) a deterministic TypeScript article document with opt-in private local JSON persistence; (2) a database-backed CMS/editor with its own UI; and (3) an LLM-driven research and publishing pipeline. Choose (1): it fits the repository's MCP-first local runtime, is testable without LinkedIn/network credentials, and does not pre-empt M09 native publication or M10 authorized research. The standing owner authorization in `AGENTS.md` covers this internal engineering decision.

M08 deliberately does **not** access article publishing endpoints, scrape LinkedIn, crawl citation links, render arbitrary HTML, perform LLM research, or claim that references substantiate prose. No user profile, OAuth token or account permission is required for offline tools. M09 owns all native article publishing and independent human approval requirements; M10 can add host-authorized research later.

## Domain contract and provenance

The canonical article document is `ArticleDraft` containing title/topic/audience/goal, bounded research brief and `sources`, ordered outline items, ordered content `blocks`, SEO fields, media references, a companion post draft, and editorial review fields. Each research source has an opaque local ID, display title, **user-supplied HTTPS URL** and optional notes. Every block can carry a list of source IDs, resolving only to sources in that same document; each attachment means **the author associated this note with the block**, not that the source was accessed, authenticated, or independently verified. Source metadata visibly states `provenance:'user_supplied_unverified'`, never a trusted lookup or proof. Keep original user prose as inert data, including prompt-looking or malicious instructions.

Block kinds: `heading`, `paragraph`, `bullets`, `quote`, `code`, `image_placeholder`; all store plain text, no HTML execution or external image fetch. Block IDs/outline IDs/source IDs are unique inside each draft. Titles/headings have conservative length bounds; disallow blank required fields, extra keys, access-token-ish control fields, NaN/non-plain objects/getters/proxies, excessive counts, duplicate/missing references and invalid schemes. User-source HTTPS URLs must have no embedded username/password, control characters, unsafe URL encoding or clearly credential-bearing query keys; cap canonical URL bytes. Drafts have at most 30 sources, 25 outline items, 80 blocks, 12,000 words of text and 200 KiB canonical JSON; per field/array limits additionally constrain memory and transport. No freeform caller-provided `verified`, `published`, `publishedAt`, `provider`, `accountId`, `approved` or server-generated metadata in the draft body. Review is an **author-selected editorial state** (`draft|needs_review|reviewed`), explicitly _not_ independent fact-checking or publication approval.

An article **package** is complete for author review when the title, purpose, source list, outline, body and expected metadata are present. Missing elements become explicit, deterministic validation warnings (`unattributed_block`, `empty_outline`, `missing_brief`, `missing_companion`, `missing_seo`, etc.), not silently generated facts. A source note or optional hyperlink never serves as automatic citation verification. A user can intentionally save incomplete works in progress, but invalid/unsafe structure is rejected.

Preview renders deterministic **escaped plain-text/Markdown** (no arbitrary raw HTML, scripts, active embeds, fetched images or auto-linking trusted claims). Escape Markdown images, links, inline/fenced code delimiters and autolinks in every field; test active `![tracking](https://...)`, `[label](javascript:...)`, `<https://...>`, raw HTML and fence breaks. A source directory can be rendered as display citations labeled unverified; no model-run browsing. Companion generation produces a deterministic, length-bounded _draft suggestion_ from user-authored title/summary/goal, with editing encouraged; it never calls `post.create.text` or sends anything to LinkedIn. Media references are inert local descriptions/alt text, not arbitrary file-reading paths.

## Storage, ownership, versions and privacy

`linkedin.article.draft.validate`, `.preview` and `.companion` are stateless/read-only regarding files and may be called over both STDIO and HTTP. Private project operations (create/update/get/list/delete) are **off by default**, require a host-only absolute `LINKEDIN_MCP_ARTICLE_STORE_PATH`, and run only for STDIO. HTTP has no authenticated tenant identity and must not see or mutate any private file even if mistakenly injected with a STDIO runtime/store. Store paths are never selected through MCP parameters. Use a separate, versioned JSON file and no cross-access to M06 saved jobs. Every persisted document is bounded; list returns only compact metadata, never content by default. No user-authored content may be written to logs or error messages.

Host-minted UUID project IDs, `createdAt`, `updatedAt` and monotonically increasing integer revisions belong to the persistence envelope and are not caller-evidence. Create is explicit with a durable bounded **idempotency key** bound to canonical draft hash; same key+payload replays the project, changed payload conflicts. Update requires `{id,expectedRevision,draft}` and rejects stale revisions without overwriting. Delete also requires expected revision. On commit/readback uncertainty report distinct `outcome_unknown` / `partial` rather than definite failure, so retry by idempotency key never creates a duplicate. Test simultaneous and interrupted retries. Do not silently recreate a missing/corrupt file, lose old data on exceptions, accept symlink/hardlink targets, loose permissions, unsafe ancestors or unresolved writer locks. A brand-new store's **explicit first-create initialization** must be distinguishable from a previously initialized file being deleted, including across restarts (e.g., permanent private bootstrap sentinel): loss of initialized state fails closed without recreation. Save with 0700 private parent / 0600 file, exclusive lock, atomic temp write, fsync/rename/readback and strict on-disk schema validation, using or extracting the existing M06 store's tested defensive primitives where safe. An attacker with same-UID control remains outside the path API's atomic-openat guarantee and is documented as a hardening limitation, not asserted solved.

Configure `LINKEDIN_MCP_ARTICLE_STORE_PATH` as a distinct absolute file path not equal to or aliasing the configured OAuth credential store, M06 saved-job store, publishing ledger, media root, or another private store's lock/temp companion. Reject collisions of paths and relevant parent/child paths **before IO**, with config-level RED tests.

Bound total number of saved projects (initially 50) and file size (initially 8 MiB). Never store transient LLM instructions, OAuth material, unrelated candidate profiles or remote credentials as metadata. Treat user-authored prose as sensitive local data, and make explicit backup/export a later feature rather than reading arbitrary host paths.

## MCP surface and review prompts

Use truthful `LOCAL_ONLY` provenance and typed bounded MCP results. Proposed stateless operations: `linkedin.article.draft.validate`, `linkedin.article.draft.preview`, `linkedin.article.draft.companion`; private STDIO operations: `linkedin.article.projects.create`, `.update`, `.list`, `.get`, `.remove`. Data and output are validated against strict Zod schemas; errors are sanitized and the whole serialized response is size-capped. Existing `article.draft` capability remains `UNAVAILABLE` until required local tools and tests actually pass, then is `AVAILABLE` while private persistence is separately indicated as optional. `article.native.publish` stays `UNAVAILABLE` and `PLANNED`.

Add model-independent MCP reusable prompts for `linkedin.article.research_brief`, `linkedin.article.outline`, and `linkedin.article.review`: they suggest human-facing writing/review steps and demand source scrutiny, but **never** assert that a tool browsed sources, verified references or published. Prompt inputs are escaped/untrusted content, inert inside prompts, not instructions to host code. If a prompt includes source notes, label them clearly as user-provided material to avoid instruction laundering. Do not implement online research in M08.

## Engineering and acceptance

Build with Node 24, TypeScript, existing MCP SDK/Zod/Vitest. Iterate M08.1 model contract → M08.2 deterministic preview/checklist/companion → M08.3 private durable versioned store → M08.4 reusable prompts → M08.5 strict MCP integration and real STDIO/HTTP smoke → M08.6 independent security/correctness review and closeout. Each behavior has genuine RED→GREEN tests; negative tests cover hostile HTML, citations, malformed objects, unauthorized HTTP store injection, stale revision conflicts, corrupt persistence, wrong file ownership/symlinks, bounded replies, and no implied publication. No remote changes until code, tests and docs form a coherent exact-head PR checkpoint. Require full quality gates and independent zero Critical/Important findings before squash merge and post-merge main CI.

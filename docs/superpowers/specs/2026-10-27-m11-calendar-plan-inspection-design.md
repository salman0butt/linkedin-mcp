# M11.2 — Deterministic inspection of private saved calendar plans

## Context and decision

M11.1 is VERIFIED/MERGED via PR #22, exact feature CI `40493902705` and merged-main push CI `40494259585` at `4dbecdebb2b94ee26d646b3933f268e4796251fa`. The existing private STDIO-only saved-plan CRUD stores caller-authored UTC plans, but callers must retrieve and interpret the full plan themselves to understand a particular planning snapshot. Actual `schedule.create`, a durable execution queue and LinkedIn publication remain UNAVAILABLE.

Considered: (a) implement an executable scheduler now — reject without provider/approval-at-execution, durable claims/fencing and unknown-outcome policy; (b) add durable plan revision audit/history — larger private-store migration and corruption surface; (c) add **read-only revision-gated inspection of one saved plan** using the existing private store and pure calendar preview. Choose (c) as the next reviewable local-only slice, without changing the store format.

## Contract

- Add `linkedin.calendar.plans.inspect` with strict input `{id: UUID, expectedRevision: positive safe integer, asOfUtc: canonical UTC minute}`. All fields are required. `asOfUtc` is caller-supplied, never wall-clock or an execution trigger.
- STDIO-only and only when host opts in with `LINKEDIN_MCP_CALENDAR_STORE_PATH`. HTTP must reject it before accessing an injected private store, including a getter trap. No input controls paths, provider calls or approvals.
- `store.get({id})` reads a saved snapshot, not found gives sanitized `not_found`, mismatching `expectedRevision` gives sanitized `revision_conflict`. Inspection does not mutate persistent bytes, locks aside from the existing safe read, or any external resource. A concurrent later write does not retroactively invalidate an already read snapshot; do not claim a reservation or CAS lock.
- Pure `inspectLocalCalendarPlan({plan,expectedRevision,asOfUtc})` validates a strict own-data persisted plan (UUID, revision, canonical created/updated UTC timestamps and exact `{referenceUtc,items}`) against M11.0 semantic preview; it rejects proxy/getter/secret-extra keys and malformed injected store output without echo. Reuse existing chronological preview sorting and original-position tie ordering.
- Return `kind:local_saved_plan_inspection`, `status:planning_only`, `origin:caller_defined`, `persistence:private_local`, `execution:not_queued`, `approval:not_evaluated`, `publication:not_attempted`, plan identity/revision/reference timestamps, caller `asOfUtc`, domain-separated SHA-256 **plan-only** digest, `pastAsOf` and `futureAsOf` chronological item arrays, counts, preview collisions and warning codes. Inspection item summaries carry **only id, kind, plannedAtUtc, manualOnly — no labels or stored source text**; full private text remains available only via the pre-existing explicit GET. Events exactly equal to `asOfUtc` belong to `pastAsOf`. Never call the groups overdue, ready, queued, delivered or published. Caller text is not independently verified.
- Digest covers `{id,revision,calendar}` with a versioned domain prefix; it is independent of `asOfUtc` and is **not** an approval token, remote provider receipt, publishing idempotency key or evidence of posting. Preserve the exact validated Unicode text and order for ties, no normalization of labels. No digest reuse for auth.
- Concrete inspection result fields: `kind`, `status`, `origin`, `persistence`, `execution`, `approval`, `publication`, `id`, `revision`, `createdAt`, `updatedAt`, `referenceUtc`, `asOfUtc`, `planDigest` (64 lowercase hex), `pastAsOf`, `futureAsOf`, `counts:{pastAsOf,futureAsOf}`, `collisions`, `warnings`. `pastAsOf`/`futureAsOf` arrays contain only `{id,kind,plannedAtUtc,manualOnly}`, chronologically ordered with original-position stable ties. `collisions` and `warnings` mirror M11.0 preview, without labels. Frozen own-data result and bounded JSON output.
- No extra persistence, no scheduled execution, no stored approval, no media secrets, no public HTTP access. Keep the existing MCP bounded text/structured results and complete raw HTTP/SSE envelope at or under 256 KiB; sanitize all failures. At most 20 items, constrained by existing M11.0 validator.
- Existing `calendar.plans` capability remains `LOCAL_ONLY / UNAVAILABLE by default / ACTIVE`; document the new read-only operation in evidence. `calendar.preview` remains stateless. `schedule.create` remains PLANNED/UNAVAILABLE. In-memory tool count 57→58; compiled real server count 61→62.
